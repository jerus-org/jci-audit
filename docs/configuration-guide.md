# Configuration guide

jci-audit has no configuration file of its own — it reads the same `deny.toml` you'd hand
`cargo-deny` directly, and treats it as the **single source of truth** for both advisory
ignores and license policy. This guide covers `deny.toml`'s fields, the two files `jci-audit
sync` derives from it, and what stays hand-authored. See
[advanced-configuration.md](advanced-configuration.md) for the release record's storage model
and CI-specific settings.

## `deny.toml`

`jci-audit init` scaffolds this template:

```toml
[advisories]
db-path = "~/.cargo/advisory-db"
db-urls = ["https://github.com/rustsec/advisory-db"]
unmaintained = "all"
yanked = "warn"
ignore = []

[licenses]
allow = [
    "MIT",
    "Apache-2.0",
    "Apache-2.0 WITH LLVM-exception",
    "BSD-2-Clause",
    "BSD-3-Clause",
    "ISC",
    "Unicode-3.0",
    "Zlib",
    "BSL-1.0",
    "CDLA-Permissive-2.0",
]

# [[licenses.exceptions]]
# name = "some-crate"
# allow = ["MPL-2.0"]

[bans]
multiple-versions = "warn"
wildcards = "allow"

[sources]
unknown-registry = "warn"
unknown-git = "warn"
allow-registry = ["https://github.com/rust-lang/crates.io-index"]
```

### `[advisories]`

| Key | Meaning |
|-----|---------|
| `db-path` / `db-urls` | Where `cargo-deny` clones/refreshes its advisory-db copy. `jci-audit release` overrides `db-path` internally to pin the checkout for reproducibility — leave these at their defaults. |
| `unmaintained` | Scope selector (`"all"` \| `"workspace"` \| `"transitive"` \| `"none"`) for reporting unmaintained crates. `"all"` checks the whole dependency graph and reports as a warning. |
| `yanked` | `"warn"` or `"deny"` for yanked crate versions. |
| `ignore` | **The canonical list of accepted advisory IDs**, each ideally with a comment explaining why. `jci-audit sync` derives `.cargo/audit.toml`'s `[advisories].ignore` from this — never edit `.cargo/audit.toml` directly. |

### `[licenses]`

| Key | Meaning |
|-----|---------|
| `allow` | The workspace-wide license allow-list. Every dependency's SPDX expression must resolve against this (or an exception) or `cargo deny check licenses` fails. |
| `[[licenses.exceptions]]` | Admits a license **only for a named crate** — the mechanism for weak-copyleft licenses (e.g. `MPL-2.0`) that you don't want to allow globally. Each entry is `name = "crate"`, `allow = ["LICENSE-ID"]`. A new copyleft dependency without an exception fails the check until consciously reviewed — this is deliberate. |

`jci-audit sync` also derives every `crates/*/about.toml`'s `accepted` list from this section —
see [about.toml](#abouttoml) below.

### `[bans]` / `[sources]`

Standard `cargo-deny` policy — `multiple-versions`/`wildcards` for dependency-graph hygiene,
`unknown-registry`/`unknown-git`/`allow-registry` to restrict where dependencies may come from.
jci-audit does not interpret these itself; they pass straight through to `cargo deny check bans
sources`. See [cargo-deny's own documentation](https://embarkstudios.github.io/cargo-deny/) for
the full field reference.

## `.cargo/audit.toml` — derived, never hand-edit

```toml
# DERIVED FILE — do not edit by hand.
[advisories]
ignore = []
```

Regenerated by `jci-audit sync` from `deny.toml [advisories].ignore`, so `cargo audit` (run on
its own, without `cargo-deny`) honours the same ignore set. A hand-edit here will be silently
overwritten the next time `sync` runs, and will be caught as drift by `sync --check` in CI in
the meantime.

## `about.toml`

If your crate ships `THIRD-PARTY-LICENSES.md` notices via [`cargo-about`](https://github.com/EmbarkStudios/cargo-about),
`jci-audit sync` also derives each crate's `about.toml` `accepted` list — but **scoped to that
crate's own dependency graph**, not a copy of `deny.toml`'s full workspace allow-list. See
[design.md §4.2](design.md#42-abouttoml--a-per-crate-spdx-aware-derivation) for the derivation
algorithm (SPDX expression evaluation against the allow-list, reachability excluding dev-only
edges).

```toml
# Derived — jci-audit sync manages this key:
accepted = [
    "Apache-2.0",
    "MIT",
    # ... only the licenses THIS crate's dependency graph actually carries
]

# Hand-authored — untouched by sync:
ignore-dev-dependencies = true

# A per-crate exception, mirroring deny.toml's [[licenses.exceptions]] — only
# written here if the exception's crate is reachable from THIS crate:
[option-ext]
accepted = ["MPL-2.0"]

# Hand-authored attribution pins for crates whose license needs disambiguating
# (e.g. a vendored C library with its own nested LICENSE files) — never touched
# by sync:
[libgit2-sys.clarify]
license = "MIT"
[[libgit2-sys.clarify.files]]
path = "LICENSE-MIT"
checksum = "..."
```

Only the top-level `accepted` array and each qualifying exception crate's `accepted` key are
managed by `sync`. Everything else — comments, `ignore-dev-dependencies`, `.clarify` blocks — is
yours; `sync` merges rather than rewrites, so hand-authored content survives every run.

In a multi-crate workspace, each `crates/*/about.toml` gets its **own** derived list, scoped to
that crate's own reachable dependencies — not the workspace's full policy copied into every
crate. See [design.md §4.2](design.md#42-abouttoml--a-per-crate-spdx-aware-derivation) for why.
